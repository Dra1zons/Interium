# Delta port — work in progress

The DeltaClient-1.2 ZIP supplied by the user is the source of `assets/delta/fonts/*` and the reference for the new `DeltaFont` adapter and fragment shader. The supplied project declares its license as "Minecraft EULA" in `fabric.mod.json`; that is not an explicit grant to redistribute all source and third-party font assets. Rights for code and fonts must be clarified before distributing a combined release. Do not label these assets GPL-3.0-only.

This is not the complete Delta GUI yet. `DeltaFont` is a 1.21.11 adapter for the original MTSDF atlases: normal colored text only, without Delta's outlines, fades, gradients or reload support. All five fonts were tested in the Minecraft 1.21.11 client with software OpenGL: shader compilation succeeded and Latin, Cyrillic, and icons rendered without the vanilla pixel font. This does not validate the Delta GUI or pixel-perfect parity. The optional FontProbe is enabled only with -Dinterium.fontProbe=true; it is not enabled during normal startup. Port GUIScreen, GUIPanel, element widgets, rounded-rectangle and blur shaders, scrolling, input, HUD, and main menu; preserve actual Delta appearance, then integrate Interium module registry. The 0.5.1 base was recovered from the last available source ZIP; the published 0.6.0 JAR is newer and must not be replaced by this incomplete project as if it were equivalent.

## Experimental GUI adaptation

`DeltaScreen` now uses GUIScreen/GUIPanel's category names/icons, panel/row geometry, sort order, search position, dark theme colors, original Onest and icon atlases. `DeltaRect` adapts the solid/outline path of Delta's `rect.fsh`; it is not the blur/glow shader. The screen is hooked to Right Shift in this OLD 0.5.1-based branch, with existing 0.5.1 modules, not the Delta module registry. Left click toggles, right click expands the two existing settings, mouse wheel scrolls, Ctrl+F focuses search. F6 opens ViaFabricPlus and F7 the old theme editor (extra compatibility keys, not Delta's original menu). Search uses Minecraft's invisible input widget and Delta fonts, not Delta's full TextField implementation. Search editing/selection differs from Delta; source widgets, theme editor, most per-module settings, original blur/glow and animation still need porting. Module binds are partially adapted: middle-click a row, then press a key or mouse button; Delete clears a bind. Bind assignments are persisted. The old theme editor does not affect hardcoded Delta theme colors. Esc closes, and mouse interactions are clipped to panels. A -Dinterium.deltaProbe=true startup flag opens the screen without a world for testing only.

Minecraft 1.21.11 / Fabric Loader 0.19.5 development client: test screen displayed, regular shader and fonts compiled, Auto Clicker toggle changed the switch visually, right-click expanded CPS, and search for `sprint` filtered the list. Right Shift opened the earlier screen revision in a newly created single-player world, with the world visible through the panels; tutorial overlay obscured part of it. This is not a test of the gameplay behavior of all modules, a test of multiplayer, or proof of exact visual parity. Build passed and 28 existing core checks passed. The later search-selection revision was checked in the test client: insertion after moving the caret and Ctrl+A selection both worked. Keyboard G was bound to Auto Clicker, persisted in the config, and toggled it in a single-player world; a side mouse button was bound to Sprint and toggled it in the same world. These tests do not verify every key, configuration migration, server, or gameplay behavior. GUI settings are not the original Delta settings. This branch remains older than the 0.6.0 JAR previously delivered to the user; no release is being offered from it.

## Early Aura and Velocity work

Added `Aura.java`, a partial adaptation of the Delta 1.21.4 Aura targeting / attack gates to Fabric 1.21.11. Configurable search/attack range, priority (view direction, distance, health), player/hostile/passive targets, crit/adaptive hit gates and pause while using an item are available via the experimental DeltaScreen. It excludes locally marked friends and scoreboard teammates, skips open screens and targets behind blocks, checks cooldown, uses visible camera rotation, and does not attack beyond configured range. These are not equivalent to the complete Delta Aura. Delta's rotation/movement correction, target visualization, shield break, inventory, mace, line-of-sight nuances and many other features are missing; no AntiBot, separate Criticals or dedicated Teams module is implemented. No modes should be called LiquidBounce or Augustus until their genuine behavior has been adapted and tested. Original LiquidBounce KillAura is a 475-line entry point plus many other modules and utilities: https://github.com/CCBlueX/LiquidBounce/blob/nextgen/src/main/kotlin/net/ccbluex/liquidbounce/features/module/modules/combat/killaura/ModuleKillAura.kt (GPL-3.0-or-later). No LiquidBounce code has been ported in this step. Augustus implementation not available in the current workspace; do not fabricate it. Preserve prior excluded modules.

`ClientVelocityMixin` provides only a partial ordinary-style Velocity: when enabled it cancels all entity velocity update packets for the local player after main-thread dispatch; not just PvP hits. It does not alter explosion-packet knockback or Delta's legit mode and may affect other server-applied movement. Its functional behavior is untested. It is disabled by default.

Build succeeded, 28 existing core checks passed. On a local 1.21.11 Fabric 0.19.5 creative test, Aura GUI opened and persisted the passive-entity setting, and after cows were moved within range, the client turned toward and visibly hit a cow with the module enabled. The player/teams/friends, critical hit, target priority, walls and range edge cases, Velocity, multiplayer, 1.16.5 protocol compatibility and behavior with other mods remain untested. Startup succeeded with the new packet mixin, which is not proof that the Velocity behavior works. Keep this development snapshot private; it is based on the older 0.5.1 code and not equivalent to the user's 0.6.0 JAR. Continue incremental porting, don't present this as completed HvH or as a release.

## Aura aiming and Speed (1.21.11)

Aura now optionally retains a valid target, rotates visibly with configurable maximum yaw/pitch change per tick (10–180 degrees), and waits for the look ray to intersect the target hitbox within the configured attack range. It checks for an intervening collider and other living entities before attacking; normal target, friend/team, crit and weapon-cooldown checks still apply. This is an incremental adaptation, not Delta's original silent rotations, movement correction, smart sprint or full shield-breaking system. Potential interactions with crystal modules and player-vs-player/network behavior remain untested.

Added Speed to Movement without changing existing module indices. Mode Strafe applies configurable horizontal client velocity along normalized movement input; BHop additionally jumps on the ground while moving. Values range from 0.20 to 0.80; default 0.36. It is disabled by default, skips GUI, flight, gliding, vehicles, sneaking, water, lava and climbing, and does not inject server-specific bypasses. It overwrites horizontal velocity while moving (including possible knockback), may conflict with Aura camera turns and other movement modules, and may be corrected or rejected by servers. Mode and speed are saved; enabled state is not saved.

Build passed and 28 existing core checks passed (not specific module tests). On local Fabric 1.21.11, an unarmored stationary cow at 10 health dropped to 6.152 after enabling Aura, while its health stayed 6.152 with a three-block wall between player and cow during a second trial. No proof of correct attack cooldown timing, criticals, target lock retention, aim speed, other entities, friends/teams, player targets, multi-player or server anti-cheat. On a dry stone runway with three seconds of forward input and a short stopping period, player X advanced roughly 12.95 blocks without Speed and 27.91 with Strafe at 0.36, in non-identical tick timing under software rendering. A BHop test showed F3 Y=91.7532 on a platform at standing Y=91, demonstrating a jump while moving; neither result establishes PvP viability or server compatibility. GUI shows Strafe/BHop and the setting; menu appearance remains the Delta-font adaptation, not a full Delta GUI. No release: the source base is older than the user's 0.6.0 and license clearance is unresolved.

## Target Strafe (Minecraft 1.21.11)

Added Movement/Target Strafe, disabled by default, using the current validated Aura target. Horizontal movement combines tangent and radial correction to circle at a configurable radius; direction, radius (1.0–5.0), speed (0.10–0.60) and movement-input requirement are configurable and persisted. Default radius 2.5, speed 0.25, clockwise and only while movement is held. Aura must be enabled and have a target; the setting can remove the input requirement for automatic circling. Radius larger than Aura's target search range may cause target loss. When active, Target Strafe takes precedence over the separate Speed module for horizontal velocity, preserving vertical velocity; it may overwrite knockback and can walk over edges. It does not claim server-specific bypass. It pauses on screens, flight, gliding, vehicles, sneak, liquids, climbing, dead entities, excessive height difference and loss of Aura target. Settings are simple DeltaScreen controls, not original Delta components.

Build passed and 28 existing core checks passed (not Target Strafe-specific). Single-player 1.21.11 survival smoke test against one stationary NoAI invulnerable cow at X/Z 110.5/101.5: player started X/Z 113/101.5 and after ~1 second of holding W stopped at 108.815/102.985 when set clockwise; after reset and reversing direction, stopped at 108.815/100.015. The test suggests circling in opposite directions and holding roughly the chosen radius, not full validation. No multiplayer, moving players, no-target transition, safety at ledges, configuration reload, or interaction with Speed/other mods tested. Circle can move player into hazards; server corrections are possible. This older 0.5.1-based branch is not a replacement for the user's 0.6.0 JAR. Earlier creative test used a cow that died, so is not evidence of a sustained orbit.

## Auto EXP and No Friend Damage (1.21.11, partial)

Added Auto EXP, disabled by default. While its configurable hold key (V by default) is down, the module selects XP bottles from the hotbar only, uses them downward every 3 ticks with temporary pitch adjustment and restores the camera pitch and, on release, the prior selected slot if the player has not manually changed it. Stops on GUI/death/disconnect and does not access main inventory. Aura, TriggerBot, Anti Fireball and crystal actions pause while Auto EXP is actively using a bottle; this interaction has not been exhaustively tested. This is not a complete port of Delta AutoEXP, which includes inventory behavior. Packets contain the downward pitch and may synchronize rotation server-side; servers and multiplayer not tested.

Added No Friend Damage, disabled by default: cancels ClientPlayerInteractionManager direct attacks by the local player against a player whose UUID is in InteriumState.friends. It does not prevent explosive damage, projectiles, alternative packet paths, or hits to unmarked scoreboard teammates. Aura and TriggerBot have separate friend/team filters already. Minecraft 1.21.11 started with the mixin enabled and the module appears in the GUI; an actual friend-player attack was NOT tested, so do not claim protection confirmed.

Offline build succeeded, with 28 older core checks that do not cover these features. A startup failure caused by registering the same key category twice was fixed by reusing a single category; game subsequently launched. In local survival with 16 bottles in hotbar slot 2 and a sword in slot 1, enabling Auto EXP and holding V for about 1.8 seconds reduced bottles to 6, gained XP and selected the sword again after release. This is a smoke test only: Mending armor repair, interruptions, inventory behavior, multiplayer and servers were not tested. A cow health-before/after attempt stayed at 10 and is inconclusive, not evidence of attack functionality. No release: older 0.5.1 source is not a replacement for lost 0.6.0; Delta licensing remains unresolved.

## Free Camera — experimental, unbuilt source (2026-11-09)
Independent implementation; not a Delta code port. A detached, unregistered OtherClientPlayerEntity camera uses physical bound WASD/jump/sneak input and redirected mouse look. Body input is cleared, ordinary Interium automation paused. Common vanilla attack/use/break/pick/inventory-click/drop routes are intercepted; existing use and breaking are stopped on entry. There is no blanket packet cancellation, server freeze, body teleport, server noclip or anti-cheat guarantee. The body remains vulnerable to falling, drowning, damage, knockback and server corrections. Other mods/alternate interaction paths are not guaranteed covered.
Camera speed is 0.1–2.0 blocks/tick (default .5), adjustable in existing DeltaScreen settings and persisted as freeCamera.speed. Camera radius is capped at 64 blocks relative to the body; unloaded chunks are not explicitly requested. Movement index 8 is appended; previous bind indices are unchanged. Enable state is not persisted. Activation from menus waits for close. Code handles disable/death/owner or world replacement/disconnect; another mod's changed camera is not overwritten. These lifecycle paths require real game validation. Phase is still absent; Auto Jump/Mordo not added. Original GUI style/assets are unchanged apart from adding the setting.
